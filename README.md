# BiomeBGC_borealPredictions

## What this is

This repository runs **Biome-BGC** — a model that simulates forest growth and carbon/water
cycling — across the Canadian boreal forest, to predict how forest productivity might change
under different future climate scenarios. It ties together other modules that do the
underlying work, and adds the scripts needed to set up the experiments, run them, and turn the
results into maps and figures. Besides the future-climate forecasts, it also includes a
workflow that validates Biome-BGC's output against real-world flux tower measurements.

## How it fits into the BiomeBGC toolkit

This project runs Biome-BGC itself through other modules:

- **`BiomeBGC_dataPrep`** — prepares and spatializes the climate data and plant/ecosystem
  parameters that Biome-BGC needs as input.
- **`BiomeBGC_core`** — runs the actual Biome-BGC model for a given area and set of inputs.
- **`BiomeBGC_validationFluxTower`** — used only in the validation workflow, below, to compare
  Biome-BGC's predictions against observed flux tower measurements.

## Repository structure

| Path | Contents |
|---|---|
| `global_validation.R` | Sets up a single SpaDES simulation run of the flux-tower validation workflow for one tower: runs `BiomeBGC_dataPrep`, `BiomeBGC_core`, and `BiomeBGC_validationFluxTower` together and compares the output against that tower's observed flux data. |
| `expt_validation.R` | The validation experiment driver. Loops over a built-in list of Canadian AmeriFlux/FLUXNET towers (location, dominant species, and paths to daily/monthly/annual flux data) and runs the validation workflow for each one. |
| `global_forecast.R` | Sets up a single SpaDES simulation run of the climate-forecast workflow: defines the study area, the spatial grid resolution, which CO2 scenario and climate model to use, and which model outputs to save. |
| `expt_forecast.R` | The main climate-forecast experiment driver. Loops over all combinations of ecoprovince, CO2 scenario, and climate model, and launches the simulations in parallel. |
| `scripts/` | Standalone R scripts for processing inputs and analyzing/visualizing outputs — e.g. preparing climate indices, mapping predicted productivity (NPP), and summarizing validation results. |
| `figures/` | Plots generated by the analysis scripts (study area map, climate summaries, validation results, productivity maps). |

## Experiment design

The validation experiment (`expt_validation.R`) runs Biome-BGC once per flux tower, using that
tower's own coordinates, dominant species, and years of record, and compares the simulated
output against the tower's observed daily, monthly, and annual flux measurements. **It expects a
local copy of the AmeriFlux/FLUXNET data for each tower (see "Running this project" below).**

The climate-forecast experiment (`expt_forecast.R`) runs Biome-BGC separately for each combination of:

- **boreal ecoprovinces** (broad ecological regions of the boreal forest)
- **2 CO2 emissions scenarios** (RCP 4.5 and RCP 8.5)
- **3 climate models** (RCM4, GCM4, Hadley)

Runs are parallelized across many processor cores to keep total runtime manageable. Expect about 2 weeks of computation time with 45 cores.

## Running this project

1. `global_validation.R` sets up and can run the validation workflow for a single flux tower —
   useful for testing.
2. `expt_validation.R` runs the validation workflow across all flux towers. Before running it,
   set `fluxDataPath` at the top of the script to the local directory holding the
   AmeriFlux/FLUXNET CSV files for each tower.
3. `global_forecast.R` sets up and can run a single climate-forecast scenario — useful for testing.
4. `expt_forecast.R` runs the full set of climate-forecast scenario combinations and is intended
   for the full experiment; it expects substantial compute resources (parallel cores) and disk
   space for outputs.
5. Once outputs are produced, the numbered scripts in `scripts/` can be run to process results
   and generate the figures used for validation and reporting.
